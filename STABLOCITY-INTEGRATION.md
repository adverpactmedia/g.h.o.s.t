# STABLOCITY Integration Contract

Status: sender and receiver implementation committed and deployed to the STABLOCITY CRM and RM demo URLs. The import page and static script have been smoke-checked. Authenticated end-to-end acceptance with a real user account is still pending; do not describe the overall integration as fully verified.

## User experience
A G.H.O.S.T. user reviews a completed Meeting Blueprint and exports a Markdown file. In their own STABLOCITY deployment they open the G.H.O.S.T. import workflow, upload the file, select an industry workspace, and optionally attach it to a contact, company or deal. A workspace-level meeting record without an attachment is valid. The user previews the destination and confirms the import.

## Required payload
- Format identifier: GHOST-STABLOCITY-MEETING
- Schema version: 1
- Stable meeting UUID generated by G.H.O.S.T.
- Meeting title and creation timestamp
- Summary, objective, friction and alignment
- Decision register and action register
- Verbal corrections and supporting evidence
- Follow-up drafts
- Optional transcript inclusion, explicitly selected by the user
- Source application and export version

## Receiver security
- Authenticate using the existing STABLOCITY session.
- Verify that the signed-in user can access and write to the selected workspace.
- Verify every selected contact, company or deal belongs to that same workspace and is not deleted.
- Never trust workspace IDs, record IDs, owner IDs or permissions supplied by the Markdown file.
- Treat imported Markdown and transcript content as untrusted text; escape on display and do not execute HTML.
- Enforce upload and content length limits.
- Prevent duplicate imports using the stable meeting UUID and workspace.
- Save a workspace-scoped meeting record and audit event.
- Optional contact/deal attachment is a reference only; it does not grant access to that record.
- Reject the import if authorization fails. Do not silently move data to another workspace.

## Authorization limitation
The existing STABLOCITY model supports workspace membership and write roles. It does not yet establish per-contract/deal access controls. Until record-level authorization is implemented consistently across list, detail, search, export and mutation paths, the product must not promise that only specifically authorized contract participants can access a deal. The integration can enforce current workspace-level authorization and same-workspace record validation, but that is a narrower guarantee.

## Release tests
- Valid workspace-level import.
- Valid contact attachment.
- Valid deal attachment.
- Valid company attachment.
- Viewer cannot import.
- User without workspace membership cannot import.
- Cross-workspace and deleted-record IDs are rejected.
- Forged workspace/record IDs in the file are ignored.
- Duplicate meeting UUID is rejected or safely idempotent.
- Malformed, oversized and hostile Markdown is rejected or safely rendered.
- Imported meeting is visible only to users with access to its workspace.
- Audit event records actor, workspace, destination and import time.
- Same tests pass in CRM and RM repositories.

## What remains outside this transfer
This Markdown handoff does not provide autonomous Zoom/Meet/Teams attendance, outbound email, calendar writes, task status synchronization, user accounts or cross-device G.H.O.S.T. history. Those are independent integrations and require separate provider credentials, data storage and authorization.
